# docprep: PDF → Markdown для базы знаний Cherry Studio

## Контекст окружения
- Репозиторий: `~/Git/RAG/docpreparation` (uv-проект; marker-pdf в `.venv`, глобальный Python не трогать)
- GPU: Radeon 8060S через **llama.cpp/Vulkan** (spawn `llama-server` происходит автоматически при первом обращении к surya; vLLM/ROCm не используется)
- Веса surya-2 GGUF — локально (`/media/llm/Models/OCR/surya-ocr-2-gguf`, проверены байт-в-байт с HF), пути задаются в `.env` через `SURYA_GGUF_LOCAL_MODEL_PATH`/`SURYA_GGUF_LOCAL_MMPROJ_PATH`
- Исходники кладём в `inbox/`, результаты появляются в `outbox/` — оба каталога вне git

## Сервисы inference (`services.sh`)
```bash
./services.sh start --ocr-proxy # РЕКОМЕНДУЕТСЯ: surya :8510 + Paddle :8512 + прокси :8511
                                 # + LLM/VLM :8080 (Qwen3.6-35B-A3B + mmproj-F32, 32,7 ГБ)
./services.sh check --deep      # статус + проба генерации
./services.sh stop              # остановить свои (чужой llama-server не трогает)
```
- `--ocr-proxy` — OCR-стек с прокси-адаптером: marker аттачится к прокси :8511,
  все пути идут на surya (прозрачный pass-through), PaddleOCR-VL (:8512) поднят
  рядом. block-OCR на Paddle — только экспериментально через
  `OCR_PROXY_BLOCK_ENGINE=paddle` (ломает table-fallback: Paddle даёт plain
  без <table>, аддендум-4 USAGE). Роутинг автоматический по содержимому,
  флаг безопасен на любом PDF; без флага — обычный режим (только surya),
  отдельного `--no-ocr-proxy` нет. Статистика маршрутов: `curl :8511/stats`.
- `prepare_doc.sh` сам аттачится к OCR-стеку (прокси :8511 приоритетнее surya
  :8510) и запускает
  **captioning фигур** через LLM-сервис (VLM-описания после каждой картинки — графика
  становится находимой в текстовом RAG; Cherry Studio сами картинки не индексирует).
  Без поднятого LLM-сервиса captioning тихо пропускается; отключение — `CAPTION_FIGURES=0`.
  Язык описаний ru/en — авто-детект документа (имя файла → текст документа → метаданные PDF,
  деф. ru), логируется; принудительно — `CAPTION_LANG`. Промпт настраивается
  встроенные промпты по языку (ru/en); переопределение — `CAPTION_PROMPT` в `.env`.
- Структурированные описания (этап 1, реализовано): `CAPTION_STRUCTURED=1` — схемы →
  prose + Mermaid (валидация mmdc, ретрай ×1, фолбэк prose) + список «Связи:»,
  таблицы → pipe-MD реконструкция «сверить с PDF». ×2–3 токенов.
  Деф. в коде выкл; в рабочем .env — ВКЛ (2026-10-19). Детали/пилот — USAGE §2.4-С.
- Вэб-страницы: юзер сохраняет страницу в MD через Obsidian Web Clipper → `inbox/*.md`;
  `scripts/prepare_web.sh [--force] [файл]` — скачивает картинки, язык по большинству
  букв, VLM-описания, QC мягкий → `outbox/<имя>/` (USAGE §2.4-В). Batch: тот же
  `scripts/launch_batch.sh` — авто-диспетчер по типу inbox (md/pdf); для MD применимы
  только `--force`/`--lang`, PDF-флаги отбрасываются; лог `logs/web_latest.log`.
- Потери таблиц marker: `Table OCR failed` → авто-ремонт [1.5] в prepare_doc
  (fast-ретрай страницы + вставка; отчёт «восстановлено/НЕ восстановлено»);
  фрагменты — ремонт пропущен (нет page-якорей). Потеря ToC-таблицы для БЗ
  допустима (см. USAGE §2.6-Б).
- Для `--use_llm` брать модель/URL из вывода `services.sh check` (строка с флагами marker).

## Базовый цикл (начинать всегда с него)
1. `./services.sh start --ocr-proxy` — модели на GPU (surya + Paddle/прокси +
   Qwen3.6-35B :8080).
2. Исходники в `inbox/`.
3. Запуск обработки — **только через `scripts/launch_batch.sh [флаги]`**: агент открывает
   пользователю видимое окно терминала с `prepare_all.sh`. НЕ запускать batch в фоне без окна.
    Флаги: `--force` (переобработка), `--pages "S[-E]"` (диапазон, деф. 1–конец),
    `--fragments K` (диапазон поочерёдно кусками — тестовые выборки и большие файлы;
    при K>1 автосклейка в один MD, после успешной склейки каталоги фрагментов
    удаляются), `--fragment-pause N` (пауза N сек между фрагментами и между
    файлами batch — охлаждение ПК, деф. 0), `--debug` (фрагменты оставить
    для проверки склейки),
     `--retry-ocr` (при QC FAIL ретрай force_ocr — по умолчанию ВЫКЛ; включать только
      когда QC показал потерю текста, напр. кириллица < 55%), `--lang ru|en`
      (язык документов пакета: VLM-описания + гейт QC — кириллица/латиница ≥55%;
      без флага авто-детект: имя файла → метаданные PDF → текст, деф. ru),
     `--no-page-anchors` (отключить метки страниц; деф. ВКЛ — каждая страница
      PDF помечена в MD строкой `⌗p.N`, N = физическая страница файла 1-based;
      нужна для ссылок из БЗ на исходную страницу; USAGE §2.3-П).
4. Агент следит за ходом по `logs/batch_latest.log` (стадии `[k/5]`, captioning `[N/M]`),
   итог — `logs/batch_latest.result`; per-file логи — `logs/<имя>.log`.
5. По завершении: `./services.sh stop` (если пользователь не просил держать).
Одиночный файл/переобработка: `scripts/prepare_doc.sh [--force] <file.pdf>`.

Типовые сценарии (копировать отсюда, детали — USAGE §2.0): проба `--pages "1-10"`
→ полный `--force`; большой файл `--fragments 4` (автосклейка, фрагменты после
склейки удаляются; `--debug` — оставить); потеря текста → `--retry-ocr`;
черновик → `CAPTION_FIGURES=0`; точечно → `scripts/prepare_doc.sh --pages "S-E" <pdf>`.

## Выбор режима marker_single
| Ситуация | Флаги |
|---|---|
| Чистый цифровой PDF | `--mode fast` (текст-слой, VLM почти не запускается) |
| Битые шрифты (кириллица ≈ 0% в QC) | `--force_ocr` |
| Скан | auto full-page OCR или `--force_ocr` |
| Кросс-страничные таблицы, формы, инлайн-математика | `+ --use_llm` (llama.cpp `:8080`; полные флаги — README, раздел 4) |
| Тест сложного фрагмента | `--page_range "5-10"` |
| Только таблицы | `--converter_cls marker.converters.table.TableConverter` |

## QC-гейт (`scripts/qc_check.py`) и лечение FAIL
| Причина FAIL | Действие |
|---|---|
| Кириллица < 55% | `--force_ocr` (шрифты без ToUnicode; обычно уже сделано ретраем) |
| Точечные лидеры оглавления | вырезать блок оглавления из `.md` вручную или прогнать без страниц оглавления (`--page_range`) |
| Переносы не склеены | постправка (sed/Qwen) или `--use_llm --block_correction_prompt "склеивай переносные русские слова…"` |
| Таблицы не распознаны | спот-чек страницы: `pdftoppm -png -r 100 -f N -l N file.pdf`; при провале — `--use_llm` или TableConverter |

## Самопроверка сложных документов
1. `pdftoppm -png -r 100 -f N -l N` страницу → сверить кусок `.md` с рендером глазами.
2. Локальная правка `.md` (переносы, склейка таблиц) → повторный `uv run python scripts/qc_check.py <md>`.

## Правила
- Готовый `.md` в БЗ Cherry Studio добавляется **только через UI** (API добавления материалов нет).
- `inbox/`, `outbox/`, `.env` никогда не коммитить (уже в `.gitignore`).
- Первый запуск marker в сессии поднимает `llama-server` сам — в логе должно быть `Vulkan0: AMD Radeon 8060S`; если llama-server отсутствует, см. README «Этап 1».
