# USAGE — возможности, примеры запуска, рекомендации и реестр требований

> Дополняет `README.md` (обоснование выбора стека — там). Здесь: как всем
> пользоваться, что измерено и почему, и трассировка «требование → функционал».
> Правило проекта: **каждое новое требование фиксируется строкой в разделе 4**
> и реализуется с примером запуска в разделе 2.

## 1. Рабочий цикл (базовый)

```bash
cp .env.example .env                 # один раз
./services.sh start --ocr-proxy      # 1) модели на GPU: surya :8510 + Paddle :8512 +
                                     #    прокси-адаптер :8511 + Qwen3.6-35B :8080
cp файл(ы).pdf inbox/                # 2) исходники
scripts/launch_batch.sh              # 3) обработка (откроется окно терминала с прогрессом)
./services.sh stop                   # 4) по завершении
```

> **Рекомендуемый старт — с `--ocr-proxy`.** Флаг поднимает OCR-стек с
> прокси-адаптером: все пути идут на surya, PaddleOCR-VL рядом и готов.
> Содержимое файла оценивает сам marker постранично — с флагом нельзя
> ошибиться (подробное пояснение и таблица маршрутов — §3.6, аддендум-3/4).
> Без флага — обычный режим (только surya); отдельного `--no-ocr-proxy` нет
> и не нужно: не указан — не поднимется. Strix Halo: одновременный подъём
> с 35B LLM — не проблема (unified memory).

Результат: `outbox/<имя>/<имя>.md` — текст + таблицы + VLM-описания графики
внутри, готовые к использованию в Obsidian и к загрузке в БЗ (Cherry Studio —
через UI).

## 2. Возможности и примеры запуска

### 2.0 Типовые сценарии — копируй и запускай

**А. Новый документ: сначала проба, потом весь** (рекомендуемая практика)
```bash
./services.sh start --ocr-proxy        # стек: surya + Paddle/прокси + Qwen (LLM)
scripts/launch_batch.sh --pages "1-10" # проба 10 стр.: скорость, кириллица, таблицы
# → глазом глянуть outbox/<имя>__p1-10/<имя>__p1-10.md
scripts/launch_batch.sh --force        # весь документ целиком (проба перезапишется)
./services.sh stop
```

**Б. Большой файл (100+ стр.): фрагментами со склейкой**
```bash
scripts/launch_batch.sh --fragments 4                      # 4 куска без пауз
scripts/launch_batch.sh --fragments 4 --fragment-pause 120 # пауза 2 мин между
                                                            # фрагментами и файлами
scripts/launch_batch.sh --fragments 4 --fragment-pause 120 --debug   # + фрагменты оставить
```
`--fragments K` делит диапазон на K кусков, обрабатываемых поочерёдно; после
успешной склейки каталоги фрагментов удаляются автоматически (деф.).
`--fragment-pause N` (сек, **деф. 0 = без паузы**) — пауза между фрагментами
**и между файлами** batch (даже без фрагментации), чтобы ПК не перегревался
на длинных прогонах; не после последнего фрагмента/файла. Каждый фрагмент —
свой resume (`.qc_pass`).

**В. Битые шрифты / потеря текста** (доля букв языка QC < 55%, «крякозябры» в текст-слое)
```bash
scripts/launch_batch.sh --retry-ocr    # при QC FAIL ретрай full-page OCR (--force_ocr)
```

**Г. Быстрый черновик** (без VLM-описаний картинок — для оценки только текста)
```bash
CAPTION_FIGURES=0 scripts/launch_batch.sh
```

**Д. Точечная проверка сложного места** (таблица, схема — без batch)
```bash
scripts/prepare_doc.sh --pages "23-25" "inbox/файл.pdf"   # outbox/<имя>__p23-25/
```

**Е. Контроль по ходу**
```bash
curl http://127.0.0.1:8511/stats       # маршруты OCR: layout/fullpage/block + ошибки
./services.sh check --deep             # статус сервисов + проба генерации
tail -f logs/batch_latest.log          # стадии + факт-скорость каждые 15 с
```
Эскалация при подозрении на потерю текста: полный прогон FAIL → `--retry-ocr`;
таблицы «разъехались» → перегнать проблемный диапазон (сценарий Д).

### 2.1 Сервисы inference — `services.sh`

| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `./services.sh start --llm-parallel 3`                                                | слотов LLM-сервера (деф. 2)                                                                                                                                                                                                                                                                                              |
| `./services.sh start --llm-model <путь.gguf>`                                         | другая LLM (например, более производительная)                                                                                                                                                                                                                                                                            |
| `./services.sh start --no-llm`                                                        | только surya (captioning будет пропущен)                                                                                                                                                                                                                                                                                 |
| `./services.sh start --ocr-proxy [--no-llm]`                                          | рекомендуемый старт: + PaddleOCR-VL (:8512) и прокси-адаптер (:8511) — все пути на surya (прозрачный pass-through), Paddle рядом; `OCR_PROXY_BLOCK_ENGINE=paddle` — экспериментальный block-OCR на Paddle (§3.6 аддендум-4); `prepare_doc.sh` цепляется к прокси автоматически; статистика маршрутов: `curl :8511/stats` |
| `./services.sh start --surya-model X.gguf --surya-mmproj Y.gguf [--surya-parallel N]` | подмена OCR-VLM за алиасом surya (тест GLM-OCR/PaddleOCR-VL; выводы — §3.6)                                                                                                                                                                                                                                              |
| `./services.sh restart` / `stop`                                                      | рестарт/остановка своих сервисов (чужие не трогает)                                                                                                                                                                                                                                                                      |
| `./services.sh check --deep`                                                          | статус + проба генерации; печатает готовые флаги `--use_llm`                                                                                                                                                                                                                                                             |

### 2.2 Пакетная обработка — `prepare_all.sh` (через `launch_batch.sh`)
| Пример                                          | Сценарий                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/launch_batch.sh`                       | все файлы inbox/ целиком                                                                                                                                                                                                                                                                                                                                                                                   |
| `scripts/launch_batch.sh --pages "1-10"`        | тестовая выборка первых 10 стр. каждого файла                                                                                                                                                                                                                                                                                                                                                              |
| `scripts/launch_batch.sh --fragments 4`         | большой файл поочерёдно 4 кусками (каждый — свой каталог `outbox/<имя>__pS-E/` и свой resume); **при K>1 куски автоматически склеиваются** в один `.md` без потерь: все части входят посимвольно, ссылки на картинки целы, `_meta.json` объединяется, мягкий QC + `.qc_pass` (скрипт `scripts/merge_fragments.py`, selftest `--selftest`); после успешной склейки каталоги фрагментов **удаляются** (деф.) |
| `scripts/launch_batch.sh --fragment-pause 120`  | пауза 120 сек **между фрагментами и между файлами** batch (файлы без фрагментации — тоже) — охлаждение ПК на длинных прогонах (деф. **0** = без паузы; не после последнего фрагмента/файла). Пример вместе: `--fragments 4 --fragment-pause 120`                                                                                                                                                            |
| `scripts/launch_batch.sh --fragments 3 --debug` | то же, но фрагменты сохраняются для ручной проверки склейки (деф. debug=false — удалять; параметр зарезервирован под доп. отладочный функционал)                                                                                                                                                                                                                                                           |
| `scripts/launch_batch.sh --retry-ocr`           | при QC FAIL ретрай `--force_ocr` (по умолчанию ВЫКЛ)                                                                                                                                                                                                                                                                                                                                                       |
| `scripts/launch_batch.sh --lang en`             | язык документов пакета: VLM-описания и гейт QC (латиница ≥55%); без флага — авто-детект на каждый файл (имя файла → текст → метаданные PDF, деф. ru); валидны только `ru`/`en`                                                                                                                                                                                                                             |
| `scripts/launch_batch.sh --no-page-anchors`     | отключить метки страниц ⌗p.N в MD (деф. **ВКЛ**, см. §2.3-П)                                                                                                                                                                                                                                                                                                                                               |
| `scripts/launch_batch.sh --force`               | переобработать даже готовое                                                                                                                                                                                                                                                                                                                                                                                |
| `CAPTION_FIGURES=0 scripts/launch_batch.sh`     | без captioning (быстрый прогон)                                                                                                                                                                                                                                                                                                                                                                            |

Дефолты диапазона: начальная 1, конечная 0 (до конца), фрагментов 1.
Прогресс во время обработки (терминал + `logs/batch_latest.log`): при аттаче
к OCR-прокси `prepare_doc.sh` каждые 15 с печатает **факт-скорость** по реальным
завершённым запросам (`[--] marker факт: 3м20с | layout 25/39 стр | 8.0 с/стр`),
в конце фрагмента — `marker Nс = X.X с/стр`, в сводной таблице batch — колонка
«с/стр» (факт = сек/страницы фрагмента).

### 2.3 Один файл — `prepare_doc.sh`
```bash
scripts/prepare_doc.sh [--force] [--retry-ocr] [--lang ru|en] [--pages "S[-E]"] [--no-page-anchors] <file.pdf> [флаги marker_single]
```
Стадии: `[1/6] marker → [2/6] captioning → [3/6] cleanup (лидеры TOC) → [4/6] QC → [5/6] force_ocr (только --retry-ocr) → [6/6] готово`.
Фрагменты (`--pages`/`--fragments`): QC в мягком режиме (FAIL = предупреждение, без ретрая).

### 2.3-П Метки страниц PDF — `⌗p.N` (деф. ВКЛ)
Каждая страница PDF открывается в MD строкой-якорем `⌗p.N`, где N — **физическая
страница PDF-файла** (1-based, как в просмотрщике; НЕ книжный номер в колонтитуле).
Назначение: из ответа/цитаты БЗ (Cherry Studio чанкует MD — метка попадает в чанк
и видна в поиске) открыть исходную страницу PDF. Греп: `grep -n '⌗p\.42' *.md`.

- Механика: marker `paginate_output=true` (через `--config_json`, прокинуто в
  prepare_doc) → сырые маркеры `{N}-----` (0-based) в выдаче → `clean_md.py`
  (стадия 3) переписывает их в `⌗p.N+1`; selftest: `clean_md.py --selftest`.
- Фрагменты: нумерация **абсолютная** (маркеры page_id из page_range — исходные
  индексы PDF); склейка `merge_fragments.py` сохраняет метки как контент.
- Авто-ремонт таблиц (§2.6-Б) использует сырые маркеры как границы секций —
  вставки попадают в конец секции нужной страницы (а не в конец документа).
- Отключение: `--no-page-anchors` (prepare_doc/prepare_all/launch_batch).
  Свой `--config_json` у пользователя подавляет автоконфиг — добавь туда
  `"paginate_output": true` вручную (об этом предупредит prepare_doc).
- Готовые книги (до 2026-10-18) меток не имеют — ретроактивно не добавляются;
  появятся при следующем репрогоне (план: вместе с `CAPTION_STRUCTURED=1`).

### 2.4 Captioning: локально / облако
Локально (дефолт): Qwen3.6-35B через `services.sh`, `CAPTION_PARALLEL=2` (оба слота).
Облако (OpenAI-совместимый шлюз; ключ `CHERRY_API_KEY` подтягивается сам):
```bash
# .env:
CAPTION_API=https://open.cherryin.net/v1
CAPTION_MODEL=qwen/qwen3-vl-30b-a3b-instruct(free)   # резерв: qwen/qwen3-vl-plus
CAPTION_PARALLEL=6
```
**Рекомендация: локально** — см. замеры §3.1. marker (OCR/layout) в облако не выносится в принципе.

### 2.4-С Структурированные описания (Mermaid / таблицы)
`CAPTION_STRUCTURED=1` (env) или `--structured` (флаг `caption_figures.py`) —
режим структурированных описаний (пилот: **8/8 валидного Mermaid**,
классификация 12/12, сущности 48/49 против prose глав; сэмпл — EPUB Vol.3).
Ветвление по типу фигуры в ОДНОМ VLM-вызове (XML-теги):
- **схема** → prose (blockquote, как обычно) + блок ```mermaid + обязательный
  текстовый список «Связи:»/«Edges:» (ретривер ищет по фразам, не по синтаксису
  — главный RAG-выигрыш структуры);
- **таблица** → pipe-MD реконструкция + пометка «*VLM-реконструкция, сверить
  с PDF*» (режим только для точечного ремонта дыр marker — surya table-OCR
  точнее на числах, VLM таблицы — страховка);
- **прочее** → prose-only (как дефолт).
Тип Mermaid выбирается по содержимому (er/flowchart/sequence/state/class/
mindmap; flowchart — универсальный фолбэк), erDiagram — только строки связей,
без атрибутных блоков (единственный источник ошибок парсинга на пилоте).
Валидация `mmdc` (npx, нужен node; `--no-sandbox` подставляется сам), ретрай ×1
с текстом ошибки, фолбэк prose-only. Идемпотентность и маркеры — прежние.
Сводка в отчёте captioning: `структура: mermaid валидно N (ретрай R, фолбэк
F), таблиц T, прочих O, ошибок E`. Цена: токены/время ×2–3 на фигуру —
включать на финальных прогонах. Деф. выкл (`CAPTION_STRUCTURED=0`).

**Апгрейд готовых MD без перегона marker** — `--redescribe` (2026-10-18):
снимает старые blockquote-описания (ru/en, prose и structured, включая edge
«маркер на строке с картинкой») и описывает фигуры заново в текущем режиме.
Экономит стадию marker (~80% времени), но **не добавляет метки страниц ⌗p**
(нужен полный прогон). Бэкап `<имя>.md.bak_caption` рядом; selftest
`caption_figures.py --selftest` (12 проверок; на бою: 871/871 блоков
снимаются чисто, идемпотентно). Граница блока — по грамматике вставки;
крайний случай: свой буллет/«|»-таблица документа вплотную к блоку могут
быть захвачены — сверяй diff против бэкапа.
```bash
./services.sh start --ocr-proxy
CAPTION_STRUCTURED=1 uv run python scripts/caption_figures.py \
    --redescribe --lang en --parallel 2 "outbox/<книга>/<книга>.md"
./services.sh stop
```

Обёртка по всем книгам сразу — `scripts/redescribe_all.sh` (паузы охлаждения
между книгами, per-book логи `logs/<имя>.redescribe.log`, фильтр-подстрока,
проверка LLM-сервиса до старта; детали/примеры — в шапке скрипта):
```bash
scripts/redescribe_all.sh                      # все книги, пауза 90с (деф.)
scripts/redescribe_all.sh --pause 120 "Vol."   # только DMRB, пауза 120с
scripts/redescribe_all.sh --pause 0 "Halpin"   # одна книга, без пауз
```

### 2.4-В Вэб-страницы: Obsidian Web Clipper → MD с VLM-описаниями
Вэб-страница сохраняется в MD расширением **Obsidian Web Clipper** (браузер) —
файл кладётся в `inbox/` (frontmatter сохраняется). Далее:
```bash
scripts/prepare_web.sh                 # все inbox/*.md
scripts/prepare_web.sh --force <файл>  # точечно, переобработка
```
Пайплайн: [1/5] картинки http(s) скачиваются локально, ссылки переписываются
(`scripts/fetch_images.py`: percent-encoding декодируется — «Схема ММ.png»;
SVG/data:URI/битые — пропускаются, остаются URL) → [2/5] язык страницы:
`--lang ru|en` > `CAPTION_LANG` > **текст** (большинство букв — основной
сигнал для вэба) > деф. `ru` → [3/5] captioning на языке страницы (маркер
`VLM-описание:`/`VLM-description:`); порог мелких для вэба — `CAPTION_MIN_BYTES`
деф. **4096** (вэб-диаграммы бывают 8–15КБ; PDF-дефолт 20КБ отсекал их) →
[4/5] cleanup + QC **мягкий** (вэб без
таблиц — норма; `.qc_pass` ставится) → [5/5] `outbox/<имя>/<имя>.md` +
картинки рядом (готово к Obsidian и БЗ). Оригинал остаётся в `inbox/`.
`prepare_all.sh` (PDF) кладёт `*.pdf` — конфликта нет; **конвенция: типы в
`inbox/` не смешиваем** — каждый скрипт берёт только свой тип, чужой
игнорируется с подсказкой в лог. Приёмка: страница
СиММА «Метамоделирование» — 5/5 картинок, cyr 82%, описания 5/5, 28с.

**Примеры (MD/вэб):**
```bash
scripts/launch_batch.sh                # авто-диспетчер: inbox/*.md -> prepare_web.sh
                                       # (окно терминала; лог logs/web_latest.log;
                                       # PDF-флаги --pages/--fragments/... отбрасываются
                                       # с подсказкой, остаются --force/--lang)
scripts/prepare_web.sh                 # то же без окна (все inbox/*.md)
scripts/prepare_web.sh --force <файл>  # точечная переобработка
scripts/prepare_web.sh --lang en <файл>  # принудительный английский (описания + QC)
CAPTION_FIGURES=0 scripts/prepare_web.sh  # только скачать картинки + QC, без VLM
```
`launch_batch.sh` — диспетчер по типу: `*.md` → `prepare_web.sh`, `*.pdf` →
`prepare_all.sh` (все флаги, как раньше); оба типа одновременно — ошибка
(конвенция); `LAUNCH_BATCH_ECHO=1` — напечатать команду вместо окна (debug).

**Язык описаний** (только `ru`/`en`): авто-детект языка документа в `prepare_doc.sh`
(каскад: `CAPTION_LANG` принудительно → кириллица в имени файла → **текст
документа** (сильнейший сигнал) → метаданные pdfinfo (слабый fallback:
переведённые издания, шаблонный Title); деф. `ru`),
результат пишется в лог: `[--] язык документа: en — текст документа (кириллица 0%); VLM-описания
на английском`. Управление в `.env`:
```bash
CAPTION_LANG=ru            # принудительно (иначе авто-детект)
CAPTION_PROMPT="…{ctx}…{lang}…"   # свой промпт-шаблон (см. ниже)
```
`CAPTION_PROMPT` — свой промпт-шаблон (переопределяет встроенные; действует
на ОБА языка). Дефолт — **встроенные промпты по языку документа**: для ru —
русский, для en — английский (инструкции на языке ответа; единый рус. шаблон
с «на английском» дал ~14% русских описаний на англ. документе — замер
Ponniah, 31/225). Плейсхолдеры: `{ctx}` — контекст (обязателен), `{lang}` —
«русском»/«английском» (нет — добавляется «Отвечай на {lang} языке.»);
`\n` — перевод строки; фигурные скобки безопасны. Если алфавит шаблона не
совпадает с целевым языком — предупреждение в лог. Промпт без `{ctx}` —
отказ с понятной ошибкой.

### 2.5 Resume, прогресс, логи, ETA
- Resume: `outbox/<имя>[__pS-E]/.qc_pass` — повторный запуск пропускает готовое.
- Прогресс: стадии `[k/6]`, captioning `[N/M] … осталось ~T`; `.status` в каталоге результата.
- Логи: `logs/<имя>.log`, сводный `logs/batch_<датавремя>.log`, для мониторинга —
  `logs/batch_latest.log` и итог `logs/batch_latest.result`.
- ETA: медианы из `logs/timings.jsonl` (сид 8.4 с/стр до накопления истории).

### 2.6 QC-гейт (`scripts/qc_check.py`)
Языкозависимый гейт: **ru** (деф.) → кириллица ≥55%, **en** → латиница ≥55%
(**среди букв** — иммунитет к пробельным паддингам таблиц); точечные лидеры
оглавления (вычищаются на [3/6]), переносы (целевого алфавита), таблицы.
Язык гейта = язык документа: флаг `--lang ru|en` (`launch_batch.sh`/`prepare_all.sh`
→ `prepare_doc.sh`) → env `CAPTION_LANG` → авто-детект (см. §2.4); в логе
`[4/6]` печатается `lang=…, cyr=…%/lat=…%`. Английские документы (напр. DMRB)
проходят QC честно — мягкий FAIL более не ожидаем.
FAIL полного документа → `[FAIL]` без ретрая (осознанный разбор); ретрай — только `--retry-ocr`.
Критерий включения ретрая: доля букв целевого языка < 55% (реальная потеря текста, битые ToUnicode-шрифты).

### 2.6-Б Потери таблиц: `Table OCR failed` / `Overflow` и авто-ремонт
Лог marker может содержать:
- `[WARNING] Table OCR failed for block /page/N/<Label>/K` — таблица страницы
  N (0-based) не прочиталась table-OCR → её содержимое теряется в MD;
- `[INFO] Overflow in columns/rows …` — ячейки вышли за предсказанную сетку
  (объединённые ячейки, OCR-шум) — теряются отдельные ячейки, таблица
  остаётся; маркер НЕ локализует overflow по страницам.

**Авто-ремонт ([1.5] в prepare_doc, полный документ):** после marker по логу
`logs/<имя>.marker.log` определяются провальные страницы; каждая перегоняется
`marker --page_range N --mode fast` (pdftext, текст-слой — часто читает то,
что не осилил table-OCR) и восстановленный контент вставляется в конец
секции страницы (границы секций — маркеры страниц `{N}-----`/`⌗p.N`, см.
§2.3-П; до их появления вставки шли в конец документа). Отчёт в логе:
`стр. N: восстановлено (строк таблицы X)` или `стр. N: НЕ восстановлено —
блок <Label>: … что потеряно`. Повторный прогон идемпотентен. Фрагменты
(`--pages/--fragments`) ремонтом не покрываются (там QC мягкий) —
пропуск с записью в лог (полный прогон документа отремонтирует).
**Рекомендация по оглавлениям:** потеря ToC-таблицы для БЗ/RAG допустима и
обычно даже лучше (номера страниц не резолвятся, точечные лидеры — шум;
названия разделов и так есть заголовками в теле). Ремонт восстановит её, но
cleanup затем вычистит лидеры — это ожидаемо. Для сканов без текст-слоя
fast-ретрай не восстановит (честный «НЕ восстановлено») — тогда точечный
разбор диапазона или `--retry-ocr` (полная 2-я попытка OCR всего документа).

### 2.7 CHM → MD (справочники PowerDesigner и подобные)
Распакованный CHM (`*.hhc` + html + картинки; имена html — хеши, порядок и
заголовки — в `.hhc`) → один MD на CHM:
```bash
uv run python scripts/chm_to_md.py --title "Имя документа" <путь/к/data.hhc>
# далее — обычные стадии:
uv run python scripts/clean_md.py "outbox/<Имя>/<Имя>.md"
uv run python scripts/qc_check.py --lang en "outbox/<Имя>/<Имя>.md"
# captioning (структурированный, скриншоты GUI -> prose/структуры):
CAPTION_STRUCTURED=1 uv run python scripts/caption_figures.py \
    --structured --lang en "outbox/<Имя>/<Имя>.md"
```
- Порядок чтения и иерархия заголовков — из `.hhc` (вложенность UL → ##/###…);
  внутренние заголовки страниц демотируются, дубль заголовка страницы
  выбрасывается.
- **Якоря источника `⌗doc:<имя>.html`** — аналог `⌗p` для PDF: перед каждой
  секцией, переживает чанкинг, грепается.
- Картинки: `.image` (PNG) → `figures/*.png`, ссылки переписываются;
  мелкие иконки <4 КБ (`--min-image-bytes`) выбрасываются.
- html вне TOC — хвостом в «Не в оглавлении» (контент не теряем);
  TOC-ссылки с `#фрагментом` на включённые страницы — тихий скип.
- marker/OCR не задействуются: текст цифровой. Selftest: `--selftest` (15).
- Принято (2026-10-18): «PowerDesigner Data Architecture Guide» (487 секций,
  157 картинок, 1,6 МБ, QC PASS) и «PowerDesigner VBScript Reference»
  (1119 секций, 46,5 МБ — честный объём справки, QC PASS; при необходимости
  дробить — по библиотекам Pd* из TOC).

### 3.6 Тест GLM-OCR и PaddleOCR-VL-1.6 как drop-in замена surya-2
(замеры 2026-10-14, balanced, стр. 1–20 «АРХИТЕКТУРА», CAPTION_FIGURES=0,
подмена за алиасом `datalab-to/surya-ocr-2` через флаги `services.sh`)

| Модель | p=8, 1 фрагмент | p=4, 2 парал. фрагмента | Текст стр. 1–20 |
|---|---|---|---|
| **surya-2 (эталон, §3.5)** | **210 с (10,5 с/стр)** | 217 с (10,9) | **69,7 КБ (100%)** |
| GLM-OCR (f16) | 410 с (20,5) | 425 с wall (21,3) | 20,5 КБ (29%) |
| PaddleOCR-VL-1.6 | 280 с (14,0) | 261 с wall (13,1) | 21,2 КБ (30%) |

**Выводы:**
1. **Обе модели несовместимы с контрактом формата surya** (промпты-контракты —
   «OCR this block image to HTML.», layout/table-rec JSON со строковым bbox
   «x0 y0 x1 y1»): bbox приходит массивом → блоки отбрасываются. GLM-OCR:
   80 skip + пустые страницы («Layout inference failed»: p=8 — стр. 9/17/18,
   p=4 — ещё больше); PaddleOCR-VL: 10 skip, пустых страниц нет, но потеря
   текста та же (~70%).
2. **Обе медленнее surya-2 через marker**: GLM −49%, Paddle −25%; выигрыша от
   p=4×2-фрагментов нет (как и у surya — §3.5, п.1).
3. На стр. 1–10 вывод GLM и Paddle **побайтово идентичен** (3653 байт) —
   выживший текст берётся из текстового слоя PDF, вклад VLM нулевой.
4. С/стр завышены (время уходит на несовместимые вызовы) и НЕ отражают
   native-скорость моделей: честное сравнение — прямая транскрипция рендеров
   через one-off llama-server (без marker), интеграция потребовала бы
   адаптера формата ответа.
5. **Решение: surya-2 остаётся OCR-движком**; drop-in замена отклонена.

**Аддендум: проверка «не учли ли параметры» (сырые запросы one-off, стр. 12).**
Параметры сервера/клиента НЕ причина: клиент surya шлёт `temperature=0, top_p=0.1,
max_tokens=2048`; llama-server корректно навязывает `json_schema` грамматикой
(layout-запрос Paddle вернул валидный, но **пустой** `[ ]` — отсюда пустые
страницы, а не «мусорный JSON»); chat-шаблоны встроены в GGUF; разрешение
(100 vs 150 dpi) на GLM-OCR не влияет. Реальные причины — контракт формата
surya (block→HTML: обе модели шлют plain text; layout: модель не знает
семантики label'ов) и для GLM-OCR — слабая кириллица даже нативно
   («Контrolные», «процедуса», потеря шапки страницы). **PaddleOCR-VL нативно
   (`<|ocr|>`, 150 dpi) читает страницу чисто и полно** (2592 симв. против 2492 у surya-эталона на той же стр., 5,5 с/стр full-page одним
   запросом) — потенциал для «отдельного OCR-сервиса с адаптером формата», если
   понадобится скорость; GLM-OCR отклонён окончательно, **веса удалены** (2,5 ГБ,
   `/media/llm/Models/OCR/GLM-OCR`, 2026-10-14).

**Аддендум-2: адаптер-прокси PaddleOCR-VL → marker (2026-10-16, реализован).**
`scripts/ocr_proxy.py` (~250 строк, stdlib+httpx) + `services.sh start --ocr-proxy`
(PaddleOCR-VL-1.6 :8512 + прокси :8511). Прокси держит алиас `datalab-to/surya-ocr-2`:
layout/table_rec/high_accuracy_bbox (full-page) → surya-2 без изменений;
block-OCR («OCR this block image to HTML.») → Paddle с промптом `<|ocr|>`, t=0,
ответ оборачивается в `<p>…</p>`. Приёмка (бедка `cell--ll3um`, полный PDF
из inbox/, CAPTION_FIGURES=0):
- **Полный документ 39 стр. через адаптер: QC PASS** (cyr 97,1%, 217K симв.),
  marker 504 с (12,9 с/стр — эталон surya 11,3; дифф с эталоном: только
  косметика шапки одной таблицы). **Block-OCR не вызывался ни разу** —
  в balanced на цифровом PDF битые страницы идут full-page (HIGH_ACCURACY,
  только surya), таблицы: 22 шт. взяты из full-page HTML + 3 из pdftext,
  fallback пуст → прокси сработал как прозрачный pass-through.
- **A/B block-OCR** (те же страницы 150 dpi, `scripts/ab_block_ocr.py`,
  ответы в `outbox/ocrtests/adapter_ab/`):

  | Стр. | surya-2 | Paddle+адаптер | Текст (симв., surya/Paddle) | Кириллица |
  |---|---|---|---|---|
  | 5 (текст) | 27,6 с | **7,0 с (−75%)** | 3559 / 3549 | 100% / 99,5% |
  | 12 (текст+табл.) | 21,6 с | **4,2 с (−81%)** | 2556 / 2560 | 99,6% / 99,6% |
  | 24 (большая таблица) | 31,5 с | **19,8 с (−37%)** | 487* / 9954 | — / 99,9% |

  \* surya словил repetition-loop (`<hr data-bbox=…>` до лимита токенов; в
  пайплайне ловится ретраями клиента) — Paddle прочитал всю таблицу без сбоя.
- **Вывод**: адаптер рабочий (0 ошибок за полный прогон, маршрутизация точная),
  block-транскрипция Paddle в 3–5× быстрее при равном качестве кириллицы и
  устойчивее на тяжёлых таблицах; **но** в marker 2.0 balanced block-OCR —
  редкий путь (table-fallback pdftext, формулы, fast-mode хирургия), основные
  затраты — layout + full-page (контракт HIGH_ACCURACY, только surya).

**Аддендум-3: почему `--ocr-proxy` — рекомендуемый старт (2026-10-16).**
Решение не зависит от типа документа: **оценку содержимого делает сам marker,
постранично и поблочно**, на ходу — заранее анализировать файл не нужно:

| Путь в marker (balanced) | Кто выполняет | Куда через адаптер (дефолт) |
|---|---|---|
| Текст читаемого PDF-слоя | pdftext (бесплатно) | — |
| Разметка «что где лежит» (layout, все страницы) | surya | surya (без изменений) |
| Полное чтение битых/скан-страниц (full-page) | surya | surya — Paddle не может: нужен HTML с координатами `data-bbox`, это часть обучения модели |
| Таблицы: сборка из текстового слоя | pdftext-эвристики | — |
| Таблицы-fallback, формулы (block-OCR) | surya | **surya — чистый pass-through**; Paddle только через `OCR_PROXY_BLOCK_ENGINE=paddle` (аддендум-4) |

Следствия:
- Флаг **безопасен на любом содержимом**: в дефолте прокси прозрачен (все
  запросы → surya, ни один не модифицируется), Paddle просто готов к работе
  рядом. Ошибиться с флагом нельзя.
- Отдельного `--no-ocr-proxy` нет намеренно: не указан `--ocr-proxy` —
  адаптер не поднимается, обычный режим только surya.
- Цена режима: ~1,7 ГБ VRAM под Paddle+прокси; на Strix Halo одновременный
  подъём с 35B LLM — не проблема (unified memory).
- Контроль в процессе: `curl :8511/stats` (счётчики surya/paddle/ошибки),
  лог маршрутов `/tmp/docprep-proxy.log`.

**Аддендум-4: block-OCR по умолчанию возвращён на surya (2026-10-16, DMRB
Vol.1 стр. 161–170).** Первый реальный вызов block-OCR за все тесты —
table-fallback (Table 4.19) — **доказал деградацию при роутинге на Paddle**:
Paddle вернул plain-строки (без колоночной структуры — и на кропе, и на
full-page), а marker'у нужен `<table>`-HTML → `clean_table_html` отклонил
ответ → таблица потеряна из выдачи (`tables_ocr_failed: 1`). После возврата
дефолта на surya те же страницы: таблицы **3/3**, Table 4.19 собрана полной
сеткой 7 колонок, 71 с. Управление: `OCR_PROXY_BLOCK_ENGINE=surya` (дефолт) |
`paddle` (опция для экспериментов: block-транскрипция в 3–5× быстрее, но
table-fallback будет падать — A/B-качество текста при этом равное §3.6-2).
Paddle-сервис поднимается и в дефолте: переключение движка — перезапуск
только прокси (`./services.sh restart --ocr-proxy`), не всего стека.
